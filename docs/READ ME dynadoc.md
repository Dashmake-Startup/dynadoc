# Problem– Market Context & Problem Statement

## Current Landscape: Fragmented Productivity Ecosystem

Today’s digital work environment is dominated by specialized tools that solve isolated problems — documents, spreadsheets, presentations, meetings, chat, design, AI — but rarely unify them.

Major competitors include:

* Microsoft Office
* Google Workspace
* Zoom
* Slack
* Notion
* Adobe Photoshop
* Figma

While powerful individually, these platforms create systemic fragmentation, redundancy, and inefficiency.



# The Current Problems Users Face

## 2. Tool Fragmentation & Context Switching

Users constantly switch between:

* Word → PowerPoint → Excel
* Slack → Zoom → Google Docs
* Photoshop → Drive → Email

This leads to:

* Context loss
* Manual copy-paste workflows
* Version mismatch
* Data inconsistency
* Reduced productivity

There is **no unified dynamic container** for structured documents + media + meetings + AI + design.



## 2. Static Documents in a Dynamic World

Traditional document systems (e.g., Word, Docs):

* Do not support structured variable synchronization across document types.
* Cannot link text across slides, spreadsheets, and design layers dynamically.
* Require manual updates when values change.
* Lack document-level intelligence.

Example:

> Change a company name → must manually update 20 slides, 3 spreadsheets, and 5 sections.

Current tools are *static containers*, not dynamic systems.



## 3. AI Is Add-On, Not Native

Modern platforms are adding AI features, but:

* AI is separated from document structure.
* AI does not deeply understand document variables or internal relationships.
* AI does not operate at the layer level in design tools.
* AI meeting summaries are isolated from structured knowledge reuse.

AI today is assistive — not structurally integrated.



## 4. Weak Granular Security & Lifecycle Control

Existing platforms lack:

* Character-level protection
* Expiration based on read/write behavior
* Automatic deletion after usage count
* Ephemeral structured document logic
* Owner-based lifecycle override rules

Most systems offer:

* File-level sharing
* Basic permissions
* No intelligent lifecycle governance

For legal, enterprise, confidential, or academic use — this is insufficient.



## 5. Disconnected Meeting & Knowledge Systems

In current ecosystems:

* Zoom records meetings.
* Slack holds conversations.
* Docs store notes.
* Knowledge bases are separate.

There is no automatic:

* Structured meeting-to-document integration
* AI knowledge graph inside documents
* Intelligent reuse of previous content across drafts

Information becomes scattered and lost.



## 6. Design Tools Are Isolated From Documents

Design platforms like Photoshop and Figma:

* Are not integrated inside document workflows.
* Do not support document variable synchronization.
* Cannot update presentation or textual content automatically.

Design and document ecosystems remain separated silos.



## 7. Export & Compliance Limitations

Current systems lack:

* Granular export control (per section, per table, per media)
* Export update reminders
* Automatic validation constraints (academic or corporate rules)
* Enforced content structure limits
* Non-copyable secure export workflows (JPG → PDF structural approach)

Compliance and controlled publishing require manual oversight.



## 8. No True Structured Document Container

A `.docx`, `.pptx`, `.pdf`, or Google Doc:

* Is a single-purpose file.
* Cannot behave as a multi-file container.
* Cannot embed structured inner documents dynamically.
* Cannot act like a version-controlled workspace.

Users must rely on folder structures, external versioning, and manual linking.



# The Core Need Emerging in Modern Work

Modern teams need:

* A unified dynamic document system
* Native AI integrated into structure
* Structured variable synchronization
* Secure document lifecycle control
* Developer-level control + non-technical accessibility
* Built-in versioning
* Media + design + data inside one container
* Dynamic publishing & translation
* Real-time collaboration without fragmentation

Current solutions partially address pieces of this — none unify it.



# How dynadoc Solves These Problems

**dynadoc** is a dynamic document processing system designed to unify documents, presentations, spreadsheets, design tools, AI interaction, collaboration, and structured content management inside a single `.ddoc` environment.

It combines developer-level control (CODE mode) with user-friendly editing (WYSIWYG mode), while introducing advanced document intelligence through variables, AI, synchronization, and security controls. It introduces a fundamentally different model:

# Implemented Features




## 1. Multi-Type Document Architecture

A single `.ddoc` document can contain multiple content types:

* Text
* Slides (with animations)
* Spreadsheets
* Worksheets
* Design tool pages (with layers support, similar to Photoshop)

All content types remain synchronized through the shared variable system.



## 2. In-Document Variable System

dynadoc supports a powerful variable system to avoid repetition of words, paragraphs, or sections.

When a variable is modified anywhere in the document, all instances are automatically synchronized.

### Variable Content Types

Variables can contain:

1. **Text**
2. **File**
3. **Folder**
4. **Rich Content (HTML + CSS)**
5. **Datetime**
6. **AI Content** (dynamic content generated and maintained via Artificial Intelligence)
7. **Inner Document Parts** (for example: a slide, spreadsheet, or table embedded inside another document)

### Variable Visibility Levels

Variables can have different scopes:

* File-level (only within the current file)
* Document-level
* Desktop-level
* Cloud-level



## 3. AI Integration

### In-Document AI Generation

* Generate AI-based content directly inside documents.

### AI Chat (Copilot-like)

* Document analysis
* Question answering
* Context-aware interaction
* For companies: generate draft documents based on previous documents in the user's knowledge base

### AI Knowledge Base Integration

* Meeting notes are automatically added to the user's AI knowledge base and drive.
* Users can query previous meetings.

### AI Image Generation in Layer-Based Editor

Inside the image editor:

* AI generation works based on layers.
* Each layer can contain its own prompt (e.g., background description, text, logo).
* Each generated layer can be adjusted independently:

  * Position
  * Scale
  * Prompt
  * Layout

This allows precise and structured AI-generated image creation.



## 4. Collaboration Features

* Reviews, comments, and suggestions
* Track changes
* Revision history
* Real-time collaboration
* Real-time chat with collaborators
* Meeting support with instant meeting reports



## 5. Protection & Security

### Granular Protection

Supports protecting or blurring:

* Entire document
* Single file
* Page
* Section
* Paragraph
* Word
* Even a single character

### Access Control

Supports multiple protection methods:

* Password protection
* Two-factor authentication

Protection rules can differ between:

* `.sddoc`
* `.xddoc`



## 6. Ephemeral Documents

Supports automatic deletion based on defined rules.

### Expiration Conditions

* Fixed datetime (e.g., January 5, 2025, 13:00)
* Relative time after creation
* Relative time after first read
* Relative time after first write

### Access Control

* Owner can decide if the document should also expire for themselves.
* Owner can exempt specific users.
* Audit logs are generated before deletion (without keeping the actual document data).

Supports:

* Read count limits
* Write count limits
* Automatic deletion after a certain number of reads or writes



## 7. Editing Modes

* Two synchronized modes:

  * CODE mode (for developers)
  * WYSIWYG mode (for non-developers)

* Quick switch between edit and view mode

* LaTeX support

* Built-in terminal (similar to VSCode)

* Customizable keyboard shortcuts (e.g., Ctrl+Shift+I for italic)



## 8. File and Navigation System

* Left-side file navigation (similar to VSCode)
* Automatic detection and listing of folders and files
* Tree navigation structure
* A `.ddoc` file can behave like a container:

  * Contains multiple files and folders within one document
  * Solves file organization issues



## 9. File Format Support

Supports:

* Word
* Excel
* PowerPoint
* PDF
* Image (read-only)
* PSD (read-only)
* Video
* Multimedia

Can open as many file types as possible in read mode (text, image, video, binary, 3D files).



## 10. Slideshow System

* Supports slides, sheets, and documents
* Live update of slideshow when the file changes (no restart required)
* Supports:

  * Background color changes
  * Video autoplay
  * Lightbox
  * Slide visibility
  * Vertical slides



## 11. Image Editor (Photoshop-like)

* Layer system for superposition
* Built-in image editor
* AI layer-based image generation



## 12. Export System

* Export to PDF (including non-editable, non-copyable method via JPG → PDF)

* Granular export:

  * Export specific tables
  * Export all tables
  * Export text, sheets, slides, images, or videos individually

* Automatic export update reminder:

  * If document changes, user is asked whether to update exported files
  * Option to export even if original export location no longer exists
  * Notification appears at bottom and on file close



## 13. Forms & Interactive Components

* Insert form elements anywhere:

  * Text fields
  * Checkboxes
  * Radio buttons
  * Buttons

* Create forms directly inside a document

* Forms can be sent without attaching the file externally



## 14. Content Constraints & Academic Controls

Supports:

* Character/word/sentence limits (maximum)
* Minimum requirements (e.g., at least 50 sentences)
* Maximum number of elements (e.g., 2 tables, 3 images, 4 videos)
* Minimum required elements

Validation occurs:

* On app close
* With popup or alert notifications
* At the top of the document



## 15. Translation System

* Translation files are displayed at the top of the interface using tab navigation (similar to Excel sheet tabs)

* Easy switching between languages

* Supports:

  * Side-by-side translation editing
  * Flow editor translation mode

* Documents automatically display the corresponding translation based on the user's locale



## 16. Document Version Control

* Built-in document version management
* Allows tracking of revisions and restoring previous versions



## 17. Automatic Content Update

* Documents automatically update when linked content changes
* Supports in-document file include/append system to avoid repetition



## 18. Additional Productivity Features

* Text completion (like Gmail) (Future plan)

* Gallery support (images + videos with thumbnails):

  * Slideshow mode available
  * Can be generated from folders or multiple files

* Lorem Ipsum generator



## 19. Account System

* Two simultaneous accounts supported:

  * Individual (Free)
  * Pro / Enterprise / Organization

* Easy switching between accounts

* Organization admin controls whether users can keep a personal account

* Default organization owner is the subscribing user

* Professional account admin is the user themselves



## 20. Drive Synchronization

If enabled:

* Cloud drive mirrors the same folder structure as the local device

* Example:

  * If document is in `C:/Download`, it will appear in the same location in the drive

* Preserves user organization structure
